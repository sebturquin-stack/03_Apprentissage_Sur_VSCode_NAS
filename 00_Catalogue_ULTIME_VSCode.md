🟦 3) Snippets natifs VSCode (Markdown)
VSCode ajoute automatiquement :

- heading1 → #
- heading2 → ##
- heading3 → ###
- ordered list
- unordered list
- table
- link
- image
- blockquote
- bold
- italic
- code fence
- inline code

👉 Tu ne peux pas les désactiver.
👉 Ils apparaissent dans la liste, c’est normal.

🟦 5) Raccourcis VSCode essentiels pour Markdown

| Action               | Raccourci            |
| -------------------- | -------------------- |
| Aperçu Markdown      | `Ctrl + Shift + V`   |
| Aperçu côte à côte   | `Ctrl + K V`         |
| Bold                 | `Ctrl + B`           |
| Italic               | `Ctrl + I`           |
| Commenter            | `Ctrl + /`           |
| Liste                | `- + espace`         |
| Liste numérotée      | `1. + espace`        |
| Ouvrir la palette    | `Ctrl + Shift + P`   |
| Suggestions          | `Ctrl + Espace`      |

🟦 6) Réglages critiques VSCode (à ne jamais oublier)
✔ Editor: Tab Completion = onlySnippets
→ OBLIGATOIRE pour déclencher tes snippets.

✔ Editor: Suggest: Show Snippets = ON
→ Pour les voir dans la liste.

✔ Editor: Snippet Suggestions = inline
→ Pour les mélanger avec les autres suggestions.

✔ Editor: Quick Suggestions = ON
→ Pour que VSCode propose automatiquement.

🟦 7) Workflow recommandé pour ton QG
🟩 7.1 Créer un nouveau dossier dans le QG
. Créer le dossier
. Créer README.md
. Taper readme-qg + Tab
. Compléter les champs
. Ajouter schémas / configs avec les snippets

🟩 7.2 Documenter un appareil
. Créer fichier .md
. appareil-config
. ipv4-config
. wifi-config (si AP)
. collapse pour cacher les détails

🟩 7.3 Documenter un schéma réseau
. mermaid-net
. Ajouter variantes
. collapse pour cacher les versions

🟦 8) Bonnes pratiques Markdown pour ton QG
. Toujours un README.md par dossier
. Toujours un sommaire
. Toujours un schéma réseau
. Toujours une section “Objectif”
. Toujours une section “Rôle dans l’infrastructure”
. Toujours une section “Dépendances”
. Toujours une section “Détails”
. Utiliser collapse pour les détails techniques
. Utiliser task-list pour les procédures
. Utiliser note-importante pour les points critiques
